Módulo 05 — MCP (Model Context Protocol)

Objetivo: mover las herramientas del Módulo 04 fuera del backend, a un servidor MCP independiente, y que el agente las descubra por protocolo en vez de tenerlas hardcodeadas en una lista de Python.

Herramientas: paquete mcp (SDK oficial de Python).

Prerequisito: Módulo 04. Este es el cierre del taller: reutiliza el loop de agente, las skills y el RAG de los módulos anteriores.

5.1 Qué resuelve MCP

En el Módulo 04, TOOLS_SCHEMA y TOOLS_IMPL vivían dentro de tu backend. Si mañana quisieras usar esas mismas herramientas desde otro proyecto, o agregar las de alguien más sin copiar y pegar código, no habría forma estándar de hacerlo.

MCP estandariza eso: un servidor MCP expone sus herramientas por un protocolo común (en este módulo, sobre stdio), y cualquier cliente MCP — tu backend, Claude Desktop, otro agente — puede:

  1. Conectarse al servidor.
  2. Pedirle la lista de herramientas disponibles (con su schema).
  3. Ejecutar una herramienta y recibir el resultado.

Es la misma idea del Módulo 04 (el modelo decide, el backend ejecuta), pero ahora “ejecutar” significa “pedírselo a un servidor MCP” en vez de llamar una función local.

5.3 Crea el servidor: backend/mcp_server.py

Este archivo va junto a la carpeta app/, no dentro. Reempaqueta calculate/get_clima/RAG del Módulo 04 (mismas herramientas, ahora servidas por protocolo) y agrega una herramienta nueva, exclusiva de este módulo: agregar una fila a una Google Sheet real. Necesitas la credencial de cuenta de servicio de Google — sigue el apéndice de credenciales §2 antes de este paso.

El correo (send_email) se queda exclusivamente en el Módulo 04 — no lo reexponemos aquí. Cada módulo de la segunda sesión tiene su propia integración real nueva (Módulo 04: correo; Módulo 05: Sheets) para que se note la diferencia; si reempaquetáramos también el correo acá, los dos módulos terminarían mostrando lo mismo con otro envoltorio.

Primero, crea backend/app/sheets_client.py:

from google.oauth2.service_account import Credentials
from googleapiclient.discovery import build

from .config import get_settings

SCOPES = ["https://www.googleapis.com/auth/spreadsheets"]


def append_row(spreadsheet_id: str, valores: list[str]) -> str:
    settings = get_settings()

    try:
        creds = Credentials.from_service_account_file(
            settings.google_service_account_path, scopes=SCOPES
        )
    except FileNotFoundError:
        return (
            "No encontré credentials/google_service_account.json. Sigue el "
            "apéndice de credenciales antes de usar esta herramienta."
        )

    service = build("sheets", "v4", credentials=creds)
    service.spreadsheets().values().append(
        spreadsheetId=spreadsheet_id,
        range="A1",
        valueInputOption="USER_ENTERED",
        insertDataOption="INSERT_ROWS",
        body={"values": [valores]},
    ).execute()

    return f"Fila agregada a la hoja: {valores}"

Agrega google_service_account_path a Settings/get_settings() en backend/app/config.py (mismo patrón que gmail_token_path del Módulo 04):

google_service_account_path: str

Y en backend/.env.example:

Ahora sí, backend/mcp_server.py completo:

from mcp.server.mcpserver import MCPServer

from app.tools import calculate, get_clima
from app.rag import search as rag_search
from app.sheets_client import append_row

mcp = MCPServer("workshop-tools")


@mcp.tool()
def calcular(expression: str) -> str:
    """Evalúa una expresión aritmética simple, por ejemplo '23 * 4 + 1'."""
    return calculate(expression)


@mcp.tool()
def clima(ciudad: str) -> str:
    """Devuelve el clima actual real de una ciudad (Open-Meteo)."""
    return get_clima(ciudad)


@mcp.tool()
def buscar_documentos(consulta: str) -> str:
    """Busca en los documentos cargados con /documents y devuelve los fragmentos más relevantes."""
    results = rag_search(consulta)
    if not results:
        return "No se encontraron documentos relevantes."
    return "\n\n".join(f'[{r["title"]}] {r["text"]}' for r in results)


@mcp.tool()
def agregar_fila_sheet(spreadsheet_id: str, valores: list[str]) -> str:
    """Agrega una fila al final de una hoja de Google Sheets. `valores` es la lista de celdas de la fila."""
    return append_row(spreadsheet_id, valores)


if __name__ == "__main__":
    mcp.run()

Si no alcanzaste a configurar la cuenta de servicio de Google, deja agregar_fila_sheet fuera (y su import de sheets_client) — el resto del servidor funciona igual.

Nota que buscar_documentos reutiliza el rag.py del Módulo 03 — el mismo RAG, ahora expuesto como herramienta de un agente en vez de aplicarse automáticamente en cada mensaje.

Smoke test real (verifica el servidor completo — descubrir y ejecutar herramientas — sin necesitar el LLM todavía). Los heredocs de bash (<< 'EOF') no funcionan igual en PowerShell, así que en vez de pegarlo en la terminal, créalo como archivo — funciona idéntico en los tres sistemas. Crea backend/smoke_test_mcp.py:

import asyncio
import sys
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


async def main():
    params = StdioServerParameters(command=sys.executable, args=["mcp_server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()
            print("Herramientas:", [t.name for t in tools.tools])

            result = await session.call_tool("calcular", {"expression": "123 * 47 + 8"})
            print("calcular ->", "\n".join(p.text for p in result.content if hasattr(p, "text")))


asyncio.run(main())

Y corre (Ubuntu/macOS: python3; Windows: python):

cd backend
python3 smoke_test_mcp.py

Deberías ver Herramientas: ['calcular', 'clima', 'buscar_documentos', 'agregar_fila_sheet'] y calcular -> 5789.

5.4 Crea el cliente: backend/app/mcp_client.py

import sys

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

from .llm_client import get_llm_client

SERVER_PARAMS = StdioServerParameters(command=sys.executable, args=["mcp_server.py"])


def _mcp_tool_to_schema(tool) -> dict:
    return {
        "type": "function",
        "function": {
            "name": tool.name,
            "description": tool.description or "",
            "parameters": tool.input_schema,
        },
    }


async def run_agent_with_mcp(messages: list[dict], max_steps: int = 4) -> tuple[str, list[dict]]:
    client = get_llm_client()
    trace: list[dict] = []

    async with stdio_client(SERVER_PARAMS) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools_response = await session.list_tools()
            tools_schema = [_mcp_tool_to_schema(t) for t in tools_response.tools]

            for _ in range(max_steps):
                result = client.chat_with_tools(messages, tools_schema)

                if not result.tool_calls:
                    return result.content or "", trace

                messages.append({
                    "role": "assistant",
                    "content": result.content or "",
                    "tool_calls": result.raw_tool_calls,
                })

                for call in result.tool_calls:
                    tool_result = await session.call_tool(call["name"], call["arguments"])
                    output = "\n".join(
                        part.text for part in tool_result.content if hasattr(part, "text")
                    )
                    trace.append({"name": call["name"], "args": call["arguments"], "result": output})
                    messages.append({
                        "role": "tool",
                        "tool_call_id": call["id"],
                        "content": output,
                    })

    return "No pude completar la tarea tras varios pasos de herramientas.", trace

run_agent_with_mcp es casi idéntico a run_agent del Módulo 04 — la diferencia es de dónde salen tools_schema (del servidor, vía list_tools()) y quién ejecuta la herramienta (session.call_tool(...) en vez de un diccionario local).

Simplificación a propósito: levantamos un servidor MCP nuevo en cada request (stdio_client lanza el proceso al entrar al async with). Es más fácil de seguir en un taller de 4 horas. En producción mantendrías una sesión MCP persistente en vez de reconectar en cada mensaje.

5.5 Conéctalo en chat.py

El endpoint pasa a ser async def, y usa run_agent_with_mcp en vez de run_agent:

from ..mcp_client import run_agent_with_mcp

@router.post("/chat", response_model=ChatResponse)
async def chat(request: ChatRequest) -> ChatResponse:
    messages = [{"role": m.role, "content": m.content} for m in request.history]

    skill = select_skill(request.message)
    skill_used = None
    if skill:
        messages.insert(0, {"role": "system", "content": skill["instructions"]})
        skill_used = SkillUsed(name=skill["name"], reason=f'Palabras clave de "{skill["name"]}" detectadas.')

    messages.append({"role": "user", "content": request.message})
    reply, trace = await run_agent_with_mcp(messages)

    tool_calls = [ToolCall(**t) for t in trace] if trace else None
    return ChatResponse(reply=reply, skill_used=skill_used, tool_calls=tool_calls)

Quitamos el bloque de RAG “automático” del Módulo 03 porque ahora buscar_documentos es una herramienta que el agente decide usar — si quieres mantener ambos comportamientos (RAG automático y como herramienta MCP), puedes dejar el bloque de rag.search de 03-rag.md también, no son excluyentes.

curl -s http://localhost:8000/chat \

(Necesitas haber cargado el documento de vacaciones del Módulo 03 con POST /documents — como el servidor MCP importa el mismo rag.py, ve los mismos documentos que ya cargaste.)

El agente debería: ver la herramienta buscar_documentos, decidir usarla, recibir el fragmento del documento, y responder con la cifra correcta. tool_calls en la respuesta debe mostrar buscar_documentos como la herramienta usada.

Si configuraste la cuenta de servicio de Google (§2 del apéndice), prueba agregar_fila_sheet — crea una hoja de prueba, comparte su ID (el que aparece en la URL entre /d/ y /edit) y pídele al chat que escriba en ella:

  -d '{"message": "Agrega una fila a la hoja TU_SPREADSHEET_ID con los valores Ana y Aprobado", "history": []}' \

Abre la hoja en el navegador y confirma que la fila nueva está ahí.

5.7 Ejercicio 1 — agrega una herramienta al servidor MCP (10 min)

Agrega una quinta herramienta a mcp_server.py (no a tools.py — esta vive solo del lado del servidor MCP, no la comparte el agente del Módulo 04). Dos opciones, elige la que más te sirva para el grupo:

Opción A — nueva de verdad:

@mcp.tool()
def contar_documentos() -> str:
    """Devuelve cuántos documentos hay cargados en la base de conocimiento."""
    from app.rag import list_documents
    return str(len(list_documents()))

Opción B — el tip rápido para mostrar el valor de MCP en vivo: si algún grupo pregunta “¿y el correo del Módulo 04, se puede usar aquí también?”, la respuesta práctica (3 líneas, se escribe en el momento) es reexponerlo igual que agregar_fila_sheet:

from app.tools import send_email

@mcp.tool()
def enviar_correo(to: str, subject: str, body: str) -> str:
    """Envía un correo real por Gmail a un destinatario, con asunto y cuerpo."""
    return send_email(to=to, subject=subject, body=body)

Esto es justo el punto del módulo: send_email ya existe (la escribiste en el Módulo 04), y no se reescribe nada — MCP solo necesita un wrapper de 3 líneas para volver a exponer una capacidad que el backend ya tenía. Buen momento para preguntarle al grupo: ¿por qué no dejamos esto por defecto desde el principio del módulo? (Respuesta: para que quede claro que calculadora/clima/RAG vienen heredados, y Sheets es la única pieza nueva de este módulo — si todo apareciera ya mezclado, no se nota qué es específico de MCP.)

Corre el smoke test del paso 5.3 de nuevo — deberías ver la herramienta nueva en la lista descubierta sin haber tocado el backend ni el agente: el cliente las descubre dinámicamente vía list_tools(). Pídele al chat algo que la dispare.

5.8 Ejercicio 2 — combina RAG automático (Módulo 03) con MCP (10 min)

En 5.5 quitamos el bloque de RAG automático del Módulo 03 para simplificar — pero, como dice la nota de arriba, no son excluyentes. Vuelve a agregar el bloque de rag.search(request.message) de 03-rag.md (sección 3.7) justo antes del messages.append({"role": "user", ...}) en chat.py, y deja también la herramienta buscar_documentos del servidor MCP.

Prueba una pregunta sobre tus documentos y observa la respuesta completa: ahora sources (RAG automático, siempre corre) y tool_calls (buscar_documentos, el agente decide si la usa) pueden aparecer juntos en la misma respuesta. Pregúntate: ¿tiene sentido tener ambos caminos al mismo conocimiento en un sistema real, o es redundante? No hay una respuesta única — depende de si quieres que siempre se consulte el conocimiento propio (RAG automático) o que el agente decida cuándo vale la pena ir a buscarlo (herramienta MCP).

5.9 Cierre del taller

Recapitulando lo que construiste en un solo backend, sin frameworks:

Bloque Qué aprendiste
Chat simple Un LLM es solo una función: mensajes entran, texto sale.
Skills Elegir instrucciones según la intención es solo lógica + prompts.
RAG “Conocimiento propio” = buscar y meterlo en el prompt.
Agentes El modelo puede decidir actuar, no solo responder — vía un loop.
MCP Esas acciones se pueden estandarizar y compartir entre proyectos.

Ideas para seguir por tu cuenta: conectar tu servidor MCP a tu propia base de datos, agregar más acciones reales (Slack, un CRM, tu calendario), o probar tu servidor MCP desde Claude Desktop en vez de tu propio backend — ya tienes la calculadora, el clima, el correo y Sheets corriendo como herramientas reales, el mismo servidor funciona igual desde cualquier cliente MCP.
