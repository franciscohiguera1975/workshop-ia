Módulo 04 — Agentes de IA

Objetivo: que el modelo deje de solo responder texto y empiece a decidir ejecutar acciones (herramientas) cuando las necesita, viendo el resultado antes de dar la respuesta final.

Herramientas: function calling vía la API compatible con OpenAI (lo soportan Groq, la API de OpenAI y vLLM con --enable-auto-tool-choice).

Prerequisito: Módulo 03. Si usas vLLM local, revisa 0.2 — necesitas levantarlo con --enable-auto-tool-choice --tool-call-parser hermes.

4.1 La idea: ReAct en 3 pasos

  1. Le mandas al modelo el mensaje del usuario y una lista de herramientas disponibles (nombre, descripción, parámetros).
  2. El modelo responde o bien con texto final, o bien pidiendo ejecutar una herramienta con ciertos argumentos.
  3. Si pidió una herramienta: la ejecutas tú (en tu backend), le devuelves el resultado como un mensaje más, y vuelves al paso 2. Repites hasta que responda con texto final.

Esto es exactamente lo que en los frameworks de agentes se llama “loop ReAct” (Reason + Act) — aquí lo vas a escribir a mano, sin ningún framework, para entender qué hace uno por dentro.

4.2 Crea backend/app/tools.py

Las tres herramientas de este módulo son reales, no simuladas: la calculadora evalúa de verdad, el clima viene de una API real (Open-Meteo, gratis y sin API key) y el correo se envía de verdad por Gmail. Para esta última necesitas credenciales de Google Cloud — sigue el apéndice de credenciales antes de llegar a 4.2.c, los pasos 4.2.a y 4.2.b no la necesitan.

4.2.a Calculadora y clima (Open-Meteo)

import ast
import operator

import requests

_OPS = {
    ast.Add: operator.add,
    ast.Sub: operator.sub,
    ast.Mult: operator.mul,
    ast.Div: operator.truediv,
    ast.Pow: operator.pow,
    ast.USub: operator.neg,
}


def _eval_node(node):
    if isinstance(node, ast.Constant):
        return node.value
    if isinstance(node, ast.BinOp):
        return _OPS[type(node.op)](_eval_node(node.left), _eval_node(node.right))
    if isinstance(node, ast.UnaryOp):
        return _OPS[type(node.op)](_eval_node(node.operand))
    raise ValueError("Expresión no soportada")


def calculate(expression: str) -> str:
    """Evalúa una expresión aritmética simple de forma segura (sin eval())."""
    try:
        tree = ast.parse(expression, mode="eval")
        return str(_eval_node(tree.body))
    except Exception as exc:
        return f"Error evaluando '{expression}': {exc}"

def get_clima(ciudad: str) -> str:
    """Clima actual real, vía Open-Meteo (geocoding + forecast, sin API key)."""
    geo = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": ciudad, "count": 1, "language": "es", "format": "json"},
        timeout=10,
    ).json()
    results = geo.get("results")
    if not results:
        return f"No encontré la ciudad '{ciudad}'."

    lugar = results[0]
    forecast = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params={
            "latitude": lugar["latitude"],
            "longitude": lugar["longitude"],
            "current_weather": "true",
        },
        timeout=10,
    ).json()
    actual = forecast.get("current_weather", {})
    temperatura = actual.get("temperature")
    descripcion = _WEATHER_CODES.get(actual.get("weathercode"), "condición desconocida")

    return f"En {lugar['name']} hace {temperatura}°C y está {descripcion} (datos en vivo de Open-Meteo)."

4.2.b Correo real (Gmail API)

Primero crea backend/app/email_client.py (necesita credentials/gmail_token.json — ver el apéndice):

import base64
from email.mime.text import MIMEText

from google.auth.transport.requests import Request
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

from .config import get_settings

SCOPES = ["https://www.googleapis.com/auth/gmail.send"]


def _get_credentials() -> Credentials:
    settings = get_settings()
    creds = Credentials.from_authorized_user_file(settings.gmail_token_path, SCOPES)

    if creds.expired and creds.refresh_token:
        creds.refresh(Request())

    return creds


def send_gmail(to: str, subject: str, body: str) -> str:
    try:
        creds = _get_credentials()
    except FileNotFoundError:
        return (
            "No encontré el token de Gmail. Corre "
            "'python scripts/gmail_auth.py' siguiendo el apéndice de "
            "credenciales antes de usar esta herramienta."
        )

    service = build("gmail", "v1", credentials=creds)

    message = MIMEText(body)
    message["to"] = to
    message["subject"] = subject
    raw = base64.urlsafe_b64encode(message.as_bytes()).decode()

    service.users().messages().send(userId="me", body={"raw": raw}).execute()
    return f"Correo enviado a {to} con asunto '{subject}'."

4.3 Enseña a llm_client.py a pedir herramientas

Agrega esto al archivo (necesita import json al inicio):

import json
from dataclasses import dataclass, field


@dataclass
class ToolCallResult:
    content: str | None
    tool_calls: list[dict] = field(default_factory=list)
    raw_tool_calls: list | None = None

Agrega un método chat_with_tools a OpenAICompatibleClient:

class OpenAICompatibleClient:
    ...
    def chat_with_tools(self, messages: list[dict], tools: list[dict]) -> ToolCallResult:
        response = self._client.chat.completions.create(
            model=self._model, messages=messages, tools=tools
        )
        message = response.choices[0].message

        if not message.tool_calls:
            return ToolCallResult(content=message.content or "")

        calls = [
            {
                "id": tc.id,
                "name": tc.function.name,
                "arguments": json.loads(tc.function.arguments or "{}"),
            }
            for tc in message.tool_calls
        ]
        raw = [
            {
                "id": tc.id,
                "type": "function",
                "function": {"name": tc.function.name, "arguments": tc.function.arguments},
            }
            for tc in message.tool_calls
        ]
        return ToolCallResult(content=message.content, tool_calls=calls, raw_tool_calls=raw)

4.4 Crea backend/app/agent.py — el loop

from .llm_client import get_llm_client
from .tools import TOOLS_SCHEMA, TOOLS_IMPL


def run_agent(messages: list[dict], max_steps: int = 4) -> tuple[str, list[dict]]:
    client = get_llm_client()
    trace: list[dict] = []

    for _ in range(max_steps):
        result = client.chat_with_tools(messages, TOOLS_SCHEMA)

        if not result.tool_calls:
            return result.content or "", trace

        messages.append({
            "role": "assistant",
            "content": result.content or "",
            "tool_calls": result.raw_tool_calls,
        })

        for call in result.tool_calls:
            fn = TOOLS_IMPL.get(call["name"])
            output = fn(**call["arguments"]) if fn else f"Herramienta desconocida: {call['name']}"
            trace.append({"name": call["name"], "args": call["arguments"], "result": output})
            messages.append({
                "role": "tool",
                "tool_call_id": call["id"],
                "content": output,
            })

    return "No pude completar la tarea tras varios pasos de herramientas.", trace

4.5 Conéctalo en chat.py

Primero, amplía el contrato de la respuesta: agrega la clase ToolCall y el campo tool_calls a ChatResponse (los dos nuevos en este módulo):

class ToolCall(BaseModel):
    name: str
    args: dict | None = None
    result: str | None = None


class ChatResponse(BaseModel):
    reply: str
    skill_used: SkillUsed | None = None
    sources: list[Source] | None = None
    tool_calls: list[ToolCall] | None = None

Después reemplaza la llamada directa al cliente por el agente:

from ..agent import run_agent

@router.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest) -> ChatResponse:
    messages = [{"role": m.role, "content": m.content} for m in request.history]

    skill = select_skill(request.message)
    skill_used = None
    if skill:
        messages.insert(0, {"role": "system", "content": skill["instructions"]})
        skill_used = SkillUsed(name=skill["name"], reason=f'Palabras clave de "{skill["name"]}" detectadas.')

    retrieved = rag.search(request.message)
    sources = None
    if retrieved:
        context = "\n\n".join(f'[{d["title"]}] {d["text"]}' for d in retrieved)
        messages.insert(0, {"role": "system", "content": f"Usa este contexto si es relevante:\n\n{context}"})
        sources = [Source(title=d["title"], snippet=d["text"], score=d["score"]) for d in retrieved]

    messages.append({"role": "user", "content": request.message})
    reply, trace = run_agent(messages)

    tool_calls = [ToolCall(**t) for t in trace] if trace else None
    return ChatResponse(reply=reply, skill_used=skill_used, sources=sources, tool_calls=tool_calls)

Nota: ya no llamamos a client.chat(...) directamente — run_agent internamente usa chat_with_tools, así que todo lo de los Módulos 02 y 03 (skills, RAG) sigue funcionando sin cambios.

4.8 Ejercicio 2 — fuerza dos herramientas en un mismo mensaje (10 min)

Pídele algo que necesite dos herramientas distintas en la misma pregunta:

curl -s http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "¿Cuánto es 15 * 15 y qué clima hace en Cuenca?", "history": []}' \
  | python3 -m json.tool

Mira el arreglo tool_calls completo: debería traer dos entradas, calculate y get_clima, cada una con su resultado — el agente decidió llamar a ambas en el mismo turno antes de armar la respuesta final.

Ahora abre app/agent.py y revisa el parámetro max_steps=4 de run_agent. Baja momentáneamente ese valor a max_steps=1 y repite la misma pregunta de dos herramientas: el agente alcanza a ejecutar una sola tanda de herramientas y tiene que responder con lo que tenga — o directamente no logra completar la tarea. Vuelve a subirlo a 4 cuando termines la prueba.

max_steps es el límite de cuántas rondas de “pedir herramienta → ejecutar → ver resultado” puede dar el agente antes de forzar una respuesta. Muy bajo y el agente se queda a medias en tareas que necesitan varios pasos; muy alto y una herramienta que falla en loop puede consumir muchas llamadas al LLM (y plata) antes de rendirse. En producción este número se ajusta según qué tan compleja es la tarea típica de tu agente.
