Módulo 02 — Skills

Objetivo: que el backend elija automáticamente qué instrucciones especializadas darle al modelo según lo que pida el usuario, en vez de usar siempre el mismo prompt genérico.

Herramientas: nada nuevo — solo Python estándar.

Prerequisito: Módulo 01.

2.1 Qué es una Skill (en este taller)

Una Skill es, en su forma más simple: una condición + un bloque de instrucciones. Si el mensaje del usuario “activa” la condición, esas instrucciones se insertan como mensaje system antes de llamar al modelo. No hay magia ni infraestructura nueva — es composición de prompts.

(En producción, una Skill real suele incluir también archivos de referencia y scripts que el modelo puede ejecutar — aquí nos quedamos con la parte conceptual: instrucciones que se cargan condicionalmente.)

2.2 Crea backend/app/skills.py

SKILLS = [
    {
        "name": "resumen",
        "keywords": ["resume", "resumir", "resumen"],
        "instructions": (
            "Actúa como un asistente de resúmenes. Responde en máximo 3 "
            "viñetas, en español, sin agregar opiniones ni información que "
            "no esté en el texto del usuario."
        ),
    },
    {
        "name": "traductor",
        "keywords": ["traduce", "traducir", "traducción", "to english", "al inglés"],
        "instructions": (
            "Actúa como traductor. Traduce el mensaje del usuario al idioma "
            "que pida (o a inglés si no especifica) y responde SOLO con la "
            "traducción, sin explicaciones adicionales."
        ),
    },
    {
        "name": "code-review",
        "keywords": ["revisa este código", "code review", "revisar código", "bug en mi código"],
        "instructions": (
            "Actúa como revisor de código senior. Señala errores y riesgos "
            "de seguridad, y propone una mejora concreta. Responde en "
            "formato de lista."
        ),
    },
]


def select_skill(message: str) -> dict | None:
    lowered = message.lower()
    for skill in SKILLS:
        if any(keyword in lowered for keyword in skill["keywords"]):
            return skill
    return None

2.3 Conecta la Skill en backend/app/routers/chat.py

Reemplaza el cuerpo de la función chat por:

from ..skills import select_skill

@router.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest) -> ChatResponse:
    client = get_llm_client()

    messages = [{"role": m.role, "content": m.content} for m in request.history]

    skill = select_skill(request.message)
    skill_used = None
    if skill:
        messages.insert(0, {"role": "system", "content": skill["instructions"]})
        skill_used = SkillUsed(
            name=skill["name"],
            reason=f'Se detectaron las palabras clave de "{skill["name"]}" en tu mensaje.',
        )

    messages.append({"role": "user", "content": request.message})
    reply = client.chat(messages)

    return ChatResponse(reply=reply, skill_used=skill_used)

2.4 Pruébalo

Sin disparar ninguna skill (debe dar skill_used: null):

curl -s http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "¿Qué día es hoy?", "history": []}' | python3 -m json.tool

Disparando la skill de resumen:

curl -s http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Resume esto: FastAPI es un framework web de Python moderno, rápido, basado en type hints, que genera documentación OpenAPI automáticamente.", "history": []}' \
  | python3 -m json.tool

Deberías ver "skill_used": {"name": "resumen", "reason": "..."}.

Disparando la skill de traductor:

curl -s http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Traduce esto al inglés: Hola, ¿cómo estás?", "history": []}' \
  | python3 -m json.tool

Deberías ver "skill_used": {"name": "traductor", "reason": "..."}.

Disparando la skill de code-review:

curl -s http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Revisa este código: def suma(a, b): return a+b", "history": []}' \
  | python3 -m json.tool

Deberías ver "skill_used": {"name": "code-review", "reason": "..."}.

Pruébalo también en el frontend

  1. Abre http://localhost:5173 (si no lo tienes abierto, cd frontend && npm run dev).
  2. Escribe el mismo mensaje del resumen de arriba: Resume esto: FastAPI es un framework web de Python moderno, rápido, basado en type hints, que genera documentación OpenAPI automáticamente.
  3. Debajo de la respuesta del asistente debe aparecer un enlace “Ver proceso” — haz clic para expandirlo.
  4. Dentro debe verse “Skill activada: resumen” con el motivo detectado — sin que hayamos tocado una sola línea de React.
  5. Prueba también un mensaje que no dispare ninguna skill (por ejemplo ¿Qué día es hoy?) y confirma que ahí no aparece el enlace “Ver proceso” (no hay nada que mostrar).

2.5 Ejercicio 1 — crea tu propia Skill (10 min)

Agrega tu propia Skill a la lista SKILLS (por ejemplo, “explicar como si tuviera 5 años”, o una para tu dominio: salud, legal, educación). Prueba que se active con las palabras clave que elegiste.

2.6 Ejercicio 2 — qué pasa cuando dos Skills compiten (10 min)

select_skill recorre SKILLS en orden y devuelve la primera que matchea — no la “mejor”, la primera. Esto tiene consecuencias reales.

Agrega una Skill nueva cuyas palabras clave se superpongan con una que ya tengas (por ejemplo, si tu Skill del Ejercicio 1 dispara con “explica”, agrega esta antes en la lista):

{
    "name": "explicacion-tecnica",
    "keywords": ["explica", "explicar"],
    "instructions": "Explica con jerga técnica, asumiendo nivel experto.",
},

Manda un mensaje que dispare ambas (“Explícame qué es Skills”) y observa cuál gana — la que está primero en la lista, sin importar cuál describe mejor la intención del usuario.

Ahora cambia el orden de las dos Skills en SKILLS y repite la prueba: el resultado cambia, aunque el mensaje del usuario sea idéntico.

Esto no es un bug — es la limitación real de un router por palabras clave: el orden importa, y dos intenciones parecidas pueden pisarse. En un sistema de producción esto se resuelve con un router más sofisticado (por ejemplo, pidiéndole al propio LLM que clasifique la intención antes de elegir la Skill) — fuera del alcance de este taller, pero vale la pena que lo sepas antes de usar este patrón en serio.

Bonus (opcional, fuera del backend) — tu Skill, pero de verdad en Claude

Todo lo de este módulo es una versión de juguete, hecha a mano, de algo que ya existe en producción: los Agent Skills de Claude (el mismo Claude con el que puede que estés armando este backend). La idea es idéntica — “instrucciones especializadas que se activan según la intención” — pero en vez de un if keyword in mensaje que programaste tú, es el propio modelo el que lee la description de cada Skill disponible y decide cuál usar.

La estructura de un Skill real

resumen-taller/
  SKILL.md

SKILL.md lleva un encabezado YAML con dos campos obligatorios y el cuerpo en Markdown con las instrucciones:

---
name: resumen-taller
description: Resume el texto que te dé el usuario en máximo 3 viñetas, en español, sin agregar opiniones ni datos que no estén en el original. Úsala cuando el usuario pida resumir un texto.
---

# Instrucciones

Cuando el usuario pida un resumen:
1. Responde en máximo 3 viñetas.
2. En español.
3. No agregues opiniones ni información que no esté en el texto original.

Dos reglas no-negociables: name tiene que ser igual al nombre de la carpeta (minúsculas, guiones, sin espacios), y description tiene que decir qué hace la Skill y cuándo usarla — es el único texto que Claude lee para decidir si la activa, así que si es vago, no se activa nunca o se activa siempre.

Cómo agregarla

  1. Comprime la carpeta resumen-taller/ en un .zip (la carpeta tiene que quedar como raíz del zip, no los archivos sueltos).
  2. En Claude: Configuración → Skills → + Añadir → sube el .zip → actívala.
  3. Pruébala pidiéndole a Claude que resuma algo, en una conversación nueva.

Alternativa sin escribir el YAML a mano: la Skill skill-creator (viene de Anthropic, aparece en tu lista de Skills) te guía conversacionalmente para crear una nueva — le describes qué quieres que haga y arma el SKILL.md por ti.

La diferencia de fondo con tu select_skill(): tu versión decide por coincidencia literal de palabras (frágil, como viste en el Ejercicio 2); un Skill real de Claude decide por comprensión del lenguaje de la description — más robusto, pero también por eso la description importa tanto: es, literalmente, el prompt del router.

Lo mismo, pero en ChatGPT

Aviso importante: ChatGPT no tiene un formato de Skill empaquetado (carpeta + SKILL.md + .zip) como Claude. El equivalente más cercano es un GPT personalizado (“Custom GPT”, creado con el GPT Builder) — no es una Skill que se “activa” dentro de una conversación normal según su descripción, sino un asistente aparte, con sus propias instrucciones fijas, al que entras directamente desde “Explorar GPTs”. Es la misma idea de fondo (“instrucciones especializadas reutilizables”), pero la mecánica de activación es distinta: aquí el usuario elige entrar a ese GPT, el modelo no decide activarlo por el contenido del mensaje.

  1. En ChatGPT: Explorar GPTs → + Crear.
  2. En la pestaña Configurar (no la de chat conversacional), completa:
    • Name: nombre corto, igual que el name del SKILL.md.
    • Description: una frase de qué hace — aparece en el listado de GPTs, es lo primero que lee quien decide usarlo.
    • Instructions: aquí va el equivalente al cuerpo del SKILL.md — las instrucciones completas de cómo debe comportarse (por ejemplo, las mismas 3 reglas de tu Skill de resumen: máximo 3 viñetas, en español, sin opiniones).
  3. (Opcional) Knowledge: sube archivos de referencia (igual que una Skill real de Claude puede traer archivos junto al SKILL.md) para que el GPT los consulte.
  4. (Opcional) Actions: si quisieras que este GPT ejecute herramientas reales (lo que verás en los Módulos 04-05), se definen aquí con un esquema OpenAPI — fuera del alcance de este bonus.
  5. Guarda y pruébalo en una conversación nueva con ese GPT.

Si lo que quieres es que el comportamiento se active automáticamente según la intención del mensaje, dentro de tu ChatGPT normal (más parecido a como funciona una Skill de Claude), la opción más cercana en ChatGPT son las Custom Instructions de la cuenta (aplican siempre, a todas las conversaciones) — no hay, al momento de este taller, un mecanismo de “varias Skills, cada una con su propia descripción, que el modelo elige según el mensaje” equivalente al de Claude.
